# DSL device internals — design (milestone 2, part B)

Status: draft for owner approval, 2026-11-13. Inputs:
`2026-11-13-milestone-2-inputs.md`; parent spec `2026-11-13-netdraw-design.md`
(Acceptance 5).

## Intent

Today a device's insides (WAN group, router, bridges, ports, VLAN interfaces,
radios, addresses) exist only when a MikroTik `.rsc` is imported. The owner
wants the DSL alone to be sufficient: a network of any vendor can be described
completely in a `.net` file, and an LLM can write it from `--help`. Proof is
Acceptance 5: `examples/home/network-dsl-only.net` (no `.rsc`) gives the same
`show --json` and a byte-identical SVG as `network.net` + the four `.rsc`.

This part is the language and the single build path. CLI editing commands
(Acceptance 6), `--help`/docs (4, 7) and scale/views (2, 3) are later parts
that build on it.

## Goals

- Drawing-level statements for device internals, nested as indented blocks
  under `device`.
- One build path: `.rsc` → statements → model. The importer is a translator;
  `buildModel` and `deriveArrows` read statements only.
- Addressing: IPv4 and IPv6 on interface addresses; several prefixes per VLAN.
- `netdraw import <file.rsc> [--as id]` prints the device block (eject).
- DSL-only home network passes Acceptance 5.

## Non-goals

- CLI commands for the new statements (part C; but the statement printer built
  here is the one C uses).
- Scale features: sibling collapse, named trunk sets, views, legend scaling (D).
- Importers for other vendors.
- A firewall evaluator. Arrows stay the existing heuristic.

## Anti-goals

- RouterOS concepts leaking into the language (lists, masquerade rules,
  datapaths, CAPsMAN). A Junos/Cisco user must not need to know them.
- Two builders that can drift. Parity must hold by construction, not only by
  test.
- Any change to the home golden SVG. The refactor is behaviour-preserving;
  `test/fixtures/home.golden.svg` must not be regenerated by the refactor
  (the fix-first commits that precede it may regenerate it, each on its own).

## Decisions made with the owner

1. **Drawing level** (option A): statements describe what is drawn; the
   importer emits them. Rejected: facts-level DSL (RouterOS in another
   spelling), and both levels (two grammars ×CLI cost).
2. **Indented blocks** under `device`; names inside a block are local
   (`ether2`, not `core.ether2`). Rejected: flat lines with full paths.
3. **Imports stay live.** `imports rsc …` still re-reads `.rsc` each run;
   `netdraw import` is a one-shot eject for dropping the `.rsc`.
4. **No mixing.** An imported device id and a hand-written `device` block with
   internals under the same id is an error; hint: `netdraw import`.
5. **Quoted port names** (`"ge-0/0/0"`) are allowed inside blocks.
6. **One build path** (approach 1 below).

## Approaches considered

1. **`.rsc` → statements → model (chosen).** The importer translates
   `DeviceFacts` into device blocks plus `allow` statements, resolving
   RouterOS inferences on the way. Parity by construction; enables eject;
   the statement printer is reused by part C. Cost: rewrite of
   `src/model/build.ts` (≈470 lines) and `src/model/l3.ts` over statements,
   ≈1–2 days.
2. **DSL blocks → synthetic `DeviceFacts`.** Smallest diff (≈½ day), but
   `router` becomes a fake masquerade rule and `route` a fake default route;
   every non-MikroTik device is disguised as RouterOS forever. Rejected: it
   contradicts decision 1.
3. **Two builders, kept equal by the parity test.** Every fix lands twice,
   drift found late as SVG diffs. Rejected.

## The language

Indentation: two spaces per level (tabs are an error). A block line belongs to
the nearest less-indented `device` or `bridge` line above it. Comments and the
existing trailing-comma continuation work inside blocks. Misindentation is a
`check` error with line and hint ("indent block lines under `device core`").

```
vlan lan   untagged color green  subnet 192.168.0.0/24
vlan guest 50,51    color blue   subnet 10.50.0.0/24, 2001:db8:50::/64
vlan lte   60       color orange subnet 192.168.88.0/24

device core model "hAP ax3" os "RouterOS 7.16"
  wan ether1     route "wan1-main" distance 1 dhcp
  wan vlan60-lte on bridge vlan 60 route "wan2-lte" distance 2 dhcp nat
  router
  bridge bridge address 192.168.0.1/24 lan
    ports ether2, ether5
    ports ether3, ether4 tagged 50, 60
    radio wifi1, wifi2, wifi1-iot, wifi1-5g, wifi2-iot ssid HomeNet, HomeNet-IoT, HomeNet-5
  bridge br-guest address 10.50.0.1/24 guest hotspot
    vlan-iface vlan50 on bridge vlan 50
    radio wifi1-guest, wifi2-guest ssid Guest
  address vlan50 2001:db8:50::1
  lease 192.168.0.200 "Printer"
  lease 192.168.0.28 "TV"

allow core.br-guest -> 192.168.0.200 "printer"
```

Existing `vlan` keeps its bare-string subnet form (`vlan lan untagged
"192.168.0.0/24"`) as a synonym, so `network.net` keeps parsing.

### Statements

| Statement | Where | Meaning (what is drawn / inferred) |
|---|---|---|
| `device <id> ["label"] [model "…"] [os "…"] [kind …]` | top | Device box. Without a label, the label is computed as today: `ID · model · LAN address · os`. `model`/`os` are new attributes. |
| `wan <iface> [on <parent> vlan <n>] [route "<name>"] [distance <n>] [dhcp [<addr>]] [nat]` | device | A member chip in the device's WAN group, in listing order. `route`/`distance` give the sub-line and the route arrow; `nat` = leads to the internet without an exported default route (today's masquerade case). |
| `router` | device | The "routing · NAT · firewall" box. Explicit; no inference. |
| `bridge <name> [address <cidr>(, <cidr>)*] [lan] [guest] [hotspot] [filtering]` | device | A bridge group. `address` → label + router→group arrow; `lan` → arrow label "LAN"; `hotspot` → sub-line + "guests, after hotspot login"; `guest` → guest style when no VLAN def applies; `filtering` = VLAN-filtering bridge (lane inference). |
| `ports <p>(, <p>)* [untagged <v>] [tagged <v>(, <v>)*] [horizon <n>]` | device or bridge | Port chips. Under a bridge = bridge members; directly under the device = standalone ports. `<v>` is a VLAN-def name or a numeric id (the translator always emits numeric ids, since table rows can list a subset of a def's ids or ids with no def). `tagged` keeps today's behaviour exactly: on a port it also draws the `<port>.<id>` table-row chip with its internal link, and those chips are not VLAN consumers. |
| `vlan-iface <name> [on <parent>] vlan <n> [address <cidr>(, <cidr>)*] [lan] [guest] [hotspot]` | device or bridge | VLAN-interface chip. Under a bridge = member of that bridge; `on` = parent interface it is stacked on. |
| `radio <iface>(, <iface>)* [tag <n>] [ssid <s>(, <s>)*]` | device or bridge | One radio chip. The listed names are the member interfaces, physical and virtual (`wifi1, wifi2, wifi1-iot, wifi1-5g, wifi2-iot`). Each stays linkable (`core.wifi1-iot`) and resolves to this chip, as today. The label is computed as today: physical radio names (`wifi1 / wifi2`) for an untagged chip, member names plus `· use-tag N` for a tagged one. Two chips on the same physical radio (bridge and br-guest in `core`) are two `radio` lines with different members. CAPsMAN radios are written in the AP's own block. |
| `address <iface> <cidr>(, <cidr>)* [lan] [guest] [hotspot]` | device | Addresses (IPv4 or IPv6) and flags on any named interface, including one that isn't drawn (ap2 `wg1`): the translator emits every `/ip address`, and the builder ignores interfaces with no chip, as today. |
| `lease <addr> ["comment"]` | device | DHCP lease served by this device: label source for `client … lease <addr>` and the set `render --all` draws. |

Names in blocks are `[a-z0-9_-]+` or a quoted string; node ids stay
`<device>/<name>`, so a quoted name containing `/` is escaped in the id
(builder picks the escape; ids must round-trip through `show <id>`).

`allow`/`route` already exist at top level. `allow <a> -> <addr>` gains an
address target, resolved to the client whose `lease` equals it (today's
forward-accept arrow).

## Build path

```
.rsc ──readRsc/importRsc──▶ DeviceFacts ──translate──▶ Stmt[] (device block + allow)
.net ──parseDsl────────────────────────────────────▶ Stmt[]
                                         all Stmt[] ──buildModel──▶ Model
```

- **Translator** (`src/rsc/`): owns every RouterOS inference that
  `build.ts`/`l3.ts` make today. WAN list → `wan` lines; default-route
  matching to WAN members (including the "next unused route by distance"
  shortcut) → `route`/`distance`; masquerade on a list holding the member →
  `nat`; `hasRouter` rule → `router`; LAN/GUEST lists and hotspots → flags;
  bridge VLAN table + `use-tag` → `tagged`/`untagged`; virtual SSIDs collapse
  into `radio` lines; CAPsMAN `cap-*` radios matched by MAC → SSIDs added to
  the AP's `radio` line (so the translator runs over all imports together);
  forward accepts → `allow`; leases → `lease`. Unmatched CAP radios keep
  today's warning.
- **`buildModel`** reads only statements. It keeps everything vendor-neutral:
  node tree, ids, styles from VLAN defs, lane inference, link expansion,
  hiding spare ports (still only on router-less devices, still `--all`),
  hints, legend. `DeviceFacts` no longer reaches `src/model/`.
- **Statement printer** (`src/dsl/`): `Stmt[]` → canonical DSL text.
  Round-trip property: `parse(print(s))` equals `s` (ignoring line numbers).
  Used by `netdraw import` now and by part C's editing commands.

## Addressing

- `vlan … subnet` takes a comma list; IPv4 and IPv6 both allowed.
- `bridge … address` and `address <iface>` take comma lists.
- `check` warns: an address outside every subnet of the VLAN it sits on; the
  same address on two interfaces. IPv6 CIDR math is needed (today only IPv4).
- Rendering: the first IPv4 address stays in the label as today; additional
  addresses become sub-lines on the chip. Home golden unchanged because the
  home fixture has one IPv4 address per interface.

## Acceptance for this part

1. `examples/home/network-dsl-only.net`, hand-written, no `imports`:
   `show --json` equal to `network.net`'s, SVG byte-identical. Test in
   `test/acceptance/`.
2. `netdraw import core.rsc --as core` (and ap1, ap2, lte) prints blocks that,
   pasted in place of the import, give the same result (test, not manual).
3. Printer round-trip test over every statement kind.
4. Existing tests, including `home.golden.svg`, pass unchanged.
5. `raw-export.rsc` fixture still imports without new warnings.
6. `check` errors for: tab or odd indentation, block line with no parent,

## Calls made by the designer (not the owner) — check these

From the builder check (2026-11-13):

- **`lan`/`guest`/`hotspot` are interface flags**, allowed on `bridge`, `vlan-iface`
  and `address`, because `lte.rsc` has a non-bridge LAN interface (`vlan60`,
  `192.168.88.1/24`). The computed device label takes the first address, in
  block order, on a `lan`-flagged interface. The translator emits block order
  matching today's `/ip address` order, which keeps the result unchanged.
- **Radio names are member interfaces** (see the table). The label stays
  computed, and every member name stays linkable.
- **`tagged`/`untagged` accept numeric ids**, and `tagged` keeps drawing
  table-row chips, so existing vlan-filtering imports render as they do today.
- **"`show --json` equal" means:** the full `show --json` output, compared
  after dropping every `line` field and the model's `file`.
- **`VlanDef.subnet: string` becomes `subnets: string[]`.** This breaks
  `show vlans` JSON. That's acceptable before 1.0, and no outside consumer
  exists. The legend sub-line joins the subnets with `, `.

Earlier:

- **`lease` is a device-block statement.** Earlier in the conversation the
  owner approved "leases stay on `client … lease`, importer stops matching
  leases". That breaks the parent spec: client labels come from the lease
  comment and `render --all` draws every lease. So the device needs a lease
  list; `client … lease` stays as the way to draw one.
- `ports … tagged/untagged` (added after the vocabulary review): required for
  lane inference.
- `nat`, `lan`, `guest`, `filtering`, `hotspot` flags: the minimum to carry
  today's inferences as plain words.
- Device label stays computed when no label is given (parity with imports).
- `vlan "<subnet>"` bare-string form stays as a synonym.
- Two-space indentation, tabs rejected.
